entries. Those media entries are not a usable event contract by themselves.
The two purpose-built stream routes below are independently traceable to
non-`ee/` MIT source; the remaining advertised media entries need endpoint-by-
endpoint classification before they can be represented as streams.

## Static routing coverage

[`source-route-inventory.json`](source-route-inventory.json) is generated by
[`audit-posthog-source-routes.py`](../../scripts/audit-posthog-source-routes.py)
against the pinned application revision. It identifies 363 static REST-router
resource registrations: 349 resolve to source outside `ee/`; 14 resolve to an
`ee/` import or an `EE_AVAILABLE` conditional branch. The latter are not
licensed by the root MIT grant and need separate permitted public evidence.

This is intentionally a resource-route *tree*, not an Endpoint inventory: the
router generates lookup segments at runtime, while HTTP methods, custom
actions, request/response schemas, authorization, and manually declared URL
patterns still require independent evidence. It therefore advances source
coverage without claiming that the 1,877 observed operations are reconstructed.
The scoped status of the 14 EE-dependent registrations is tracked separately
in [the EE route-resolution ledger](ee-resolution.md).
